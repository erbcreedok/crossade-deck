## 0. Как войти в проект

```bash
cd client2
npm test            # vitest — 547 тестов (юниты)
npx tsc --noEmit    # типы
npx vite build      # прод-сборка
npx vite            # dev-сервер
npx playwright test # e2e/визрегрессия (нужен запущенный dev или свой baseURL)
```

Роуты (`src/main.tsx`, в проде под `/v2/`): `playground` — песочница/UI-kit, `table` — стол,
`motion` — стенд анимаций, `solitaire` — Косынка, `no-ui` — дебаг-стенд её логики, иначе меню.

**Весь client2 — ЦЕЛИКОМ на канвасе (Pixi v8), и HTML в приложении быть не должно** (решение
владельца, 2026-07-31): проект обязан переноситься на платформы без DOM. Топбар с кнопками —
общий канвасный `ui/TopBar.ts`; в песочнице HTML уже не осталось. Исключения сознательные:
`/no-ui` (дебаг-стенд логики), скроллбары и слайдер зума песочницы/`/motion` (аффорданс СТЕНДА
для мыши), и пока — экраны Косынки, которые переедут вместе с переписью её визуального слоя.

**Git:** активная ветка — **`feat/solitaire-scene-engine`** (перепись Косынки, ждёт приёмки и
мерджа в `main`); всё запушено, дерево чистое. CI на пуше гоняет гейт (server/client/client2 +
e2e) и деплоит зелёный **`main`** на `/v2/` — фича-ветка выкачена туда же руками
(`scripts/deploy.sh client`), поэтому первый же пуш в `main` её перезатрёт. Коммитим по-русски,
префиксами (feat/fix/refactor/chore), с `Co-Authored-By`.

## Последнее — сессия 2026-07-31 (перепись Косынки на общий слой)

Пасьянс сел на `SceneEngine`: своего ввода, камеры и драга у него больше нет, геометрия и
попадание дропа идут по ОДНОМУ дереву слотов, экраны — на канвасе. Разбор целиком —
[`SOLITAIRE-REBUILD-HANDOFF.md`](./SOLITAIRE-REBUILD-HANDOFF.md) §0.

Что из этого общее и пригодится другим сценам:

- **`ui/OverlayPanel.ts`** — канвасный экран фазы (затемнение + заголовок + подпись + кнопки).
  Меню, победа, поражение, пауза — любой игре; поэтому общий, а не «экраны Косынки».
- **`slot/layouts.pile({cell})`** — резерв места для ПУСТОЙ кучи. Без него опустевшая группа
  меряется в 0×0: пропадает из раскладки родителя и перестаёт ловить дроп — ровно тогда, когда в
  неё и надо положить. Этого не хватало самому слот-контракту.
- **Доска фиксированного размера, под экран её вписывает камера** (issue #68) — рабочий рецепт
  для игровой сцены: размер карты не скачет от ширины окна, ресайз не пересобирает сцену, а на
  узком экране всё видно в зуме и приближается пинчем.

Гейты: `tsc` чист · `npm test` 538/538 · `vite build` · playwright **173/173** (было 161).

## Предыдущее — сессия 2026-07-31 (общий слой сцены + канвасная обвязка)

Разбор брака визуального слоя Косынки (см. [`SOLITAIRE-REBUILD-HANDOFF.md`](./SOLITAIRE-REBUILD-HANDOFF.md))
дал главный вывод: **общий слой должен существовать ДО того, как на него садится игра.** Пасьянс
писался, пока общего слоя не было, и оброс своим вводом, своей камерой и своим драгом.

- **`engine/sceneEngine.ts`** — общая обвязка сцены, слой между `CanvasApp` и конкретной сценой.
  Вынесена РЕФАКТОРИНГОМ из `playgroundEngine.ts` (3047 → 2586 строк). В ней: полотно и слои,
  камера целиком (пан/зум/пинч/колесо/инерция/клампы/скроллбары/авто-скролл у кромки), ввод через
  `InputRouter` с хит-тестом и ховером, `DragContext` + `SingleDrag`, реестр дроп-зон с подсветкой
  по СПОСОБНОСТЯМ груза, сессии «подглядеть», цикл кадра и слитые тени.
  Сцена реализует только `draggables()`/`everyElement()`/`homeOf()`; остальное — швы с рабочими
  умолчаниями. **Сцена без своих особенностей не пишет ни строчки ввода и камеры.**
- **`ui/TopBar.ts`** — канвасная верхняя панель (см. правило «HTML быть не должно» выше). Живёт в
  экранном слое `chrome` — вне камеры, не панится и не зумится.
- **`InputRouter.pickOverlay(sx, sy)`** — HUD спрашивается ПЕРВЫМ, до карт: панель нарисована
  поверх сцены, и палец по кнопке не должен вместо неё хватать карту под ней.
- **Камера работает в подпрямоугольнике под HUD** (`chromeInsetTop`): иначе верх контента навсегда
  заезжает под непрозрачную панель — кламп упирается в 0 и доскроллить нечем.
- Песочница переведена на всё это и осталась зелёной: e2e **161/161** (было 158/159).

Косынка на это и села (см. «Последнее» выше) — порядок §3 REBUILD-хендоффа пройден целиком.

## 1. Текущее состояние (evergreen)

### Линия «анимации / цензура скрытой карты»
- **Лицо скрытой карты**: обычная карта, номинал «?», амбер-«фак» вместо масти
  (`fingerContent.ts` + `engine/cardTextures.ts`). Не блюр, не жёлтый фон.
- **Масти** ♠♥♦♣ — SVG из единого источника (`symbols.ts`), одинаково в HTML и в канвасе
  (Pixi `Graphics.svg`). Эмодзи из client2 убраны (кроме текстовых кейсов).
- **ДЕФОЛТ цензуры = «TG-пыль» (частицы).** Выбрано владельцем. Живёт на реальной скрытой
  карте (`ui/Card`): скрытая карта = чистый фон (`hiddenBg`) + оверлей `ParticleField`,
  крутится в `Card.step`, держит цикл бодрым (`resting=false`), прячется при перевороте.
  Дефолт-рычаги и `dustParams` — в `censorConfig.ts` (один источник для стенда И доски).
  Значения: частица 5 / свапы 25 / дрожание 1 / частота 1, мерцание ВЫКЛ, пыль замедлена ×3
  (`DUST_TIME_SCALE`, «как было на 0.3x» — множитель времени в частицах, а не глобальный
  ползунок). Видно на `/playground` («скрытая (пыль)»). `/table` пока БЕЗ hidden — см. open-tasks §B.4.
- **Стенд `/motion`** — dev-витрина, целиком в канвасе, сравнивает варианты «цензуры»
  (остальные 3 = «фигуры для других кейсов»):
  - **CPU-мозаика** (настраиваемая рычагами) — `censorMotion.ts` + `engine/censorField.ts`;
  - **GPU-ремап** (стейтлесс шейдер, «моргает») и **GPU ping-pong** (ограниченное поле
    смещений, не расплывается) — `engine/censorGpu.ts`;
  - **частицы «TG-пыль»** (стиль Telegram-спойлера) — `engine/censorParticles.ts`;
  - секция **«Тряска рядов»** (пресеты row-shear).
- Рычаги на `/motion`: частица / свапы / дрожание / частота, скорость, тумблеры
  «уменьшить движение» (reduce-motion, замораживает время), «мерцание», «двигать».
- Шрифт: **Handjet** (кириллица + казахский), не VT323.

### Прочее client2 (высокоуровнево, вне этой линии — детали в `CLAUDE.md`/памяти)
- **Песочница `/playground`** — UI-kit/сторибук на канвасе (drag-and-drop, пан/зум,
  скроллбары). Движок `engine/playgroundEngine.ts` поверх общего `engine/sceneEngine.ts`.
- **UI-kit** `src/game/ui/`: `Button`, `Toggle`, `Stepper`, `Segmented`, `controls` (декларативные

## 2. Модульные решения (атомарные элементы — что переиспользовать, не изобретать)

| Модуль | Что это | Ключевое |
|---|---|---|
| `symbols.ts` | SVG-масти + фак, единый источник | `symbolCanvasSvg` (для Pixi, без viewBox) vs `suitSvg` (HTML) |
| `fingerContent.ts` | контент лица скрытой карты | `buildContent()`, `drawFinger()`, `AMBER` |
| `censorMotion.ts` | ЧИСТАЯ математика цензуры | swap-dance / row-shear / combo, `CENSOR_PRESETS`, jitter |
| **`censorConfig.ts`** | **ЧИСТЫЙ конфиг цензуры — источник правды для стенда И доски** | `DANCE_DEFAULT` (5/25/1/1), `DUST_FLICKER=false`, `DUST_TIME_SCALE=1/3`, `dustParams()`, `dustPoints()`; есть тест |
| `engine/censorSource.ts` | Pixi-извлечение силуэта фака | `buildFingerGrid(app,block)` (сетка) + `buildFingerDustPoints(app,step,cx,cy)` (облако точек) |
| `engine/censorField.ts` | императивный CPU-рендер по любой пиксель-сетке | держит рабочую сетку свапов; `update(t)` |
| `engine/censorGpu.ts` | GPU-цензура (кастомный Pixi-фильтр) | «remap» стейтлесс; «pingpong» = поле смещений с возвратом (ограничено) |
| `engine/censorParticles.ts` | Telegram-пыль | позиция/alpha частицы = чистая функция возраста; флаги `flicker`, `timeScale` |
| `ui/Card.ts` (скрытая карта) | живая пыль на реальной карте | `hiddenBg` + `ParticleField`-оверлей; крутит в `step`, `resting=false`, прячет при флипе |
| **`engine/sceneEngine.ts`** | **ОБЩАЯ ОБВЯЗКА СЦЕНЫ — база для любой игры со столом** | камера + ввод + драг + дроп-зоны + «подглядеть» + цикл и тени + экранный HUD; сцена даёт только `draggables`/`everyElement`/`homeOf`, прочее — швы |
| `ui/TopBar.ts` | канвасная верхняя панель (HTML в приложении не держим) | кнопки слева, статус справа; слой `chrome` вне камеры; ввод — через движок, как у карт |
| `ui/OverlayPanel.ts` | канвасный ЭКРАН ФАЗЫ (меню/итог/пауза) | затемнение + заголовок + подпись + кнопки; `activeButtons()` — скрытая панель не ловит ввод |
| **`solitaire/tree.ts`** | геометрия Косынки: ОДНО дерево слотов на рендер и на дроп | доска фиксированного размера, под экран её вписывает камера; приём — `caps.drop.accept` из `solitaireRules` |
| `solitaire/scene.ts` | `SolitaireScene extends SceneEngine` | своего ввода/камеры/драга нет; домен — `canDrag`/`beginDrag`/`resolveDrop`/`onElementBlocked` |
| **`engine/panZoom.ts`** | приклеиваемый пан/зум для сцен БЕЗ своего движка (`/motion`) | `attachPanZoom(app, content, opts)`; сценам на `SceneEngine` не нужен — камера уже в базе |
| `engine/viewport.ts` | чистая математика камеры | x/y/zoom, clamp, инерция (fling), `state()` для скроллбаров |
| `engine/inputRouter.ts` | стейт-машина жестов | none/drag/pan/pinch/button/hover; домен — в колбэках |
| `ui/controls.ts` | декларативные контролы | `Configurable.params()` → `Stepper`(number)/`Toggle`(bool); `attachControls` |
| `censorDemo.ts` + `CensorDemo.tsx` | стенд `/motion` | всё в канвасе; секции = заголовок+контролы+карты; DOM = топбар+скроллбары |
| `docs/animation-levers.md` | дизайн-референс рычагов | уровни (движок/геймдизайнер/юзер), назначения, что забыли/перегибаем |

**Принцип, который держим:** контролы в канвасе сами ввод не слушают — их клики роутит
`InputRouter` (через `attachPanZoom` → `opts.buttons`), чтобы кнопки не спорили за pointer с паном.
