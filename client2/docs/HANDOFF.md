## 0. Как войти в проект

```bash
cd client2
npm test            # vitest — 591 тест (юниты)
npx tsc --noEmit    # типы
npx vite build      # прод-сборка
npx vite            # dev-сервер
npx playwright test # e2e/визрегрессия (нужен запущенный dev или свой baseURL)

node scripts/sb-check.mjs --drag   # проверка каталога В БРАУЗЕРЕ (сторибук должен быть поднят)
```

**`solitaire #7` — ИЗВЕСТНО ФЛАКОВЫЙ тест, дефект теста, а не кода (issue #104).** Падает примерно
раз на пять прогонов, и одинаково — что на текущем коде, что на отложенном через `git stash`.
Прежняя запись в этом файле винила CPU-конкуренцию со сторибуком; **это было неверно**: тест падает
и при мёртвом сторибуке. Увидев его красным, не ищите регрессию — перепрогоните и сверьтесь с
`git stash`; настоящая регрессия воспроизводится, флак — нет.

Storybook при этом всё равно лучше гасить на время `npx playwright test`: два Chromium дерутся за
CPU и замедляют весь прогон.

Роуты (`src/main.tsx`, в проде под `/v2/`): `playground` — песочница/UI-kit, `table` — стол,
`motion` — стенд анимаций, `solitaire` — Косынка, `no-ui` — дебаг-стенд её логики, иначе меню.

**Весь client2 — ЦЕЛИКОМ на канвасе (Pixi v8), и HTML в приложении быть не должно** (решение
владельца, 2026-07-31): проект обязан переноситься на платформы без DOM. Топбар с кнопками —
общий канвасный `ui/TopBar.ts`; в песочнице HTML уже не осталось. Исключения сознательные:
`/no-ui` (дебаг-стенд логики), скроллбары и слайдер зума песочницы/`/motion` (аффорданс СТЕНДА
для мыши), **Storybook** (см. ниже). Косынка исключением быть перестала: там HTML не осталось совсем.

**Storybook (`npm run storybook`) — сознательное dev-исключение.** Он на React и HTML, но это
инструмент разработчика, а не приложение: в прод-бандл его код не попадает (недостижим из
`main.tsx`). Условие, которое это исключение удерживает: **стори поднимают НАСТОЯЩИЕ Pixi-компоненты**
через общий канвас-хост `engine/kitScene.ts`; HTML-макета компонента быть не может. Если однажды
понадобится «просто нарисовать кнопку в HTML, чтоб быстрее» — исключение кончилось, это уже вторая
реализация UI.

**Переносимость на iOS и кросс-плей** — отдельный разбор: [`PORTABILITY.md`](./PORTABILITY.md).

**Git:** ветка `main`, всё запушено, дерево чистое. CI на пуше гоняет гейт (server/client/client2
+ e2e) и деплоит зелёный `main` на `/v2/`. Коммитим по-русски, префиксами
(feat/fix/refactor/chore), с `Co-Authored-By`.

## Последнее — сессия 2026-08-01 (каркас Storybook + разбор переносимости)

Заведён НАСТОЯЩИЙ Storybook 9 (`npm run storybook`, :6006, локально) как каталог канвасного
UI-kit. Сделан **только каркас** и обкатан на минимуме — наполнение идёт отдельными шагами, по
указанию владельца: какие элементы переезжают из песочницы, решает он.

Что важно знать про устройство:

- **Один WebGL-контекст на весь сторибук.** Браузер держит около 16; наивный подход («каждая стори
  монтирует свой `Application`») упирается в потолок через десяток переключений и гасит ВСЁ разом.
  Поэтому витрина берётся из пула, переключение стори = `reattach` + `rebuild`, а не новый канвас.
  Проверено: обход всех стори БЕЗ единой перезагрузки превью даёт `created` ровно по числу РАЗНЫХ
  наборов опций сцены (32 стори → 6 сцен, живых одновременно не больше 4 при cap=3), канвас в
  документе всегда один. Пул лежит на `globalThis`, не в области модуля, иначе HMR начал бы
  плодить контексты. Мерить этим: `node scripts/sb-check.mjs`.
- **`autodocs` выключен намеренно** — docs-страница монтирует все стори раздела разом, а один
  канвас в N блоков не поместится. Вернуться к докам можно, добавив «оживить по клику».
- **`.storybook/preview-head.html` обязателен.** Pixi печёт текст в текстуру ОДИН раз при создании;
  без объявления Handjet на странице `ensureFonts()` ждать нечего, и все подписи запекаются
  фолбэком с чужими метриками. Каталог, который врёт про типографику, хуже отсутствующего.
- **`viteFinal` чинит три вещи из `vite.config.ts`**: `base` (`/v2/` сломал бы статическую сборку),
  `server.port` (отобрал бы 5174 у dev и Playwright), плагин `live-build-info` (инжектит в чужой HTML).

**Найдено этим каталогом (не чинилось — решение владельца).** `engine/capabilities.ts` определяет
способность по НАЛИЧИЮ метода: `asFlippable` смотрит на `requestFlip`, который есть у любой карты,
и флаг `flippable` в расчёт не берётся. Поэтому груз всегда несёт `flip`, зона ПЕРЕВОРОТ его
принимает и подсвечивается, а `requestFlip()` потом возвращает `false` и не делает ничего — то
самое «зона обещает глаголом то, чего не сделает», от которого предостерегает весь остальной код.
В песочнице не всплывало: там нет карты с `flippable:false`. Чинить надо в движке (предикат должен
читать флаг), разбор — в стори `Механики/Способности и дроп-зоны` и в issue #103.

Гейты: `tsc` чист · `npm test` **585/585** (было 533) · `vite build` · playwright **173/173**.

## Последнее — сессия 2026-08-01, ночь (секции песочницы переехали в общий слой)

Каркас наполнен: секции стенда перестали быть методами `PlaygroundEngine` и стали свободными
функциями над ОДНИМ контрактом — `game/kit/context.ts`, `SectionContext`. Подпись секции:
`(ctx, at) => { bottom, width }`. Песочница и витрина каталога отдают этот контракт каждая по-своему
и получают одну и ту же секцию; двух реализаций одного экрана не существует ни минуты.

Переехали: «Карты — варианты» (`kit/cardVariants.ts`), «Кнопки» (`kit/buttons.ts`), «Дропзоны»
(`kit/dropzones.ts`), «Дроп-индикатор» (`kit/dropIndicator.ts`), «Фишки и фигуры» (`kit/pieces.ts`),
«Стопки» (`kit/stacks.ts`), «виджеты контролов» (`kit/widgets.ts`), «Управление» → порт команд
(`kit/commandPort.ts`). Иконки и геометрия грипа — `kit/markerIcons.ts`.

**Метки захвата переехали в `SceneEngine`.** Метка («ручка» цели: грип едет с грузом, якорь стоит
дома) — общий механизм стола, generic по элементу. Пока он жил в песочнице, любая другая сцена
обязана была либо копировать плумбинг, либо показывать стопки без ручек. Теперь в базе: поля,
`mountMarkers`, хит-тест захвата в `pickElement`, груз из host в `beginDrag`, `followTo`/`endFollow`,
`update` в `renderScene`. Песочница оставила себе только своё — режим «тащить всю стопку».

**Не переехали (и почему).** «Поле» и «Игровые зоны (борды)» — их МЕХАНИКА живёт не в билдере, а в
драг-роутинге песочницы (`onDragMoved`/`resolveDrop`/`refreshZoneHomes`/`applyFieldHomes`). Вынести
билдер и оставить роутинг значило бы показать в каталоге КАРТИНКУ борда, по которой ничего нельзя
перетащить, — ровно то, от чего предостерегает правило «нелегальный дроп ничего не изменил
выглядит как полностью мёртвый драг». Их перенос = вынос роутинга дропа в общий слой, это отдельная
работа. Мультиселект тем более: он завязан на состояние сессии выделения в песочнице.

**Дефект каркаса, найденный при проверке в браузере.** `KitScene.key` отдавал МАССИВ значений, а пул
делал `new KitScene(JSON.parse(key))` и получал массив вместо объекта опций. Ошибки не возникало —
просто КАЖДАЯ опция стори (высота карты, паддинг, камера) молча заменялась дефолтом. Ключ и его
разбор вынесены в `engine/kitSceneKey.ts` (без Pixi → проверяемо в node), с тестом на обратимость.

Гейты: `tsc` чист · `npm test` **591/591** · `vite build` · playwright **173/173** (кроме известного
флака `solitaire #7`, см. §0 и issue #104).

## Предыдущее — сессия 2026-07-31 (перепись Косынки на общий слой)

Пасьянс сел на `SceneEngine`: своего ввода, камеры и драга у него больше нет, геометрия и
попадание дропа идут по ОДНОМУ дереву слотов, экраны — на канвасе. Разбор целиком — в тикете
эпика [#78](https://github.com/erbcreedok/crusade-deck/issues/78).

Что из этого общее и пригодится другим сценам:

- **`ui/OverlayPanel.ts`** — канвасный экран фазы (затемнение + заголовок + подпись + кнопки).
  Меню, победа, поражение, пауза — любой игре; поэтому общий, а не «экраны Косынки».
- **`slot/layouts.pile({cell})`** — резерв места для ПУСТОЙ кучи. Без него опустевшая группа
  меряется в 0×0: пропадает из раскладки родителя и перестаёт ловить дроп — ровно тогда, когда в
  неё и надо положить. Этого не хватало самому слот-контракту.
- **Доска фиксированного размера, под экран её вписывает камера** (issue #68) — рабочий рецепт
  для игровой сцены: размер карты не скачет от ширины окна, ресайз не пересобирает сцену, а на
  узком экране всё видно в зуме и приближается пинчем.

Гейты: `tsc` чист · `npm test` 533/533 · `vite build` · playwright **173/173** (было 161).

**Два правила, которые пережили этот эпик и стоят дороже него** (полный разбор — в #78):

1. **Общий слой должен существовать ДО того, как на него садится игра.** Пасьянс писался, пока
   `SceneEngine` не было, и оброс своим вводом, своей камерой и своим драгом — вышла параллельная
   реализация, которую владелец не принял. Сначала выносим общее, потом строим игру.
2. **Зелёные гейты про канвас не значат НИЧЕГО.** Pixi в node не исполняется: `tsc`, `vitest` и
   `vite build` визуальный слой не видят в принципе — так уже прошли мимо `baseScale=1` (карта
   втрое больше слота) и смещение на полкарты. Любую правку рендера проверять руками в браузере
   через дев-хуки (`__fd`, `__sol`, `__menu`, `__kit`): канвас не отдаёт ни DOM-узлов, ни ролей. И
   отдельно: тест «нелегальный дроп ничего не изменил» не доказывает ничего — он даёт тот же
   результат, что и полностью неработающий драг.

- **Песочница `/playground`** — UI-kit/полигон на канвасе (drag-and-drop, пан/зум,
  скроллбары). Движок `engine/playgroundEngine.ts` поверх общего `engine/sceneEngine.ts`.
  С 2026-08-01 у роли «каталог состояний» появился отдельный адресат — Storybook; что именно из
  песочницы туда переезжает, решает владелец поштучно. Правило переезда: **выносить рефакторингом,
  не копированием** — общий билдер уходит в `src/game/kit/<секция>.ts` с сигнатурой
  `(ctx: KitContext, at: Pt) => {bottom, width}`, и `PlaygroundEngine` в ТОМ ЖЕ коммите
  переключается на него. Копия билдера в стори — отклоняемое изменение.
- **UI-kit** `src/game/ui/`: `Button`, `Toggle`, `Stepper`, `Segmented`, `controls` (декларативные
  контроллеры), `Card`, `DropZone`, `Piece`, `ShadowLayer`, `TopBar` (канвасная верхняя панель).

## 2. Модульные решения (атомарные элементы — что переиспользовать, не изобретать)

| Модуль | Что это | Ключевое |
|---|---|---|
| `symbols.ts` | SVG-масти + фак, единый источник | `symbolCanvasSvg` (для Pixi, без viewBox) vs `suitSvg` (HTML) |
| `fingerContent.ts` | контент лица скрытой карты | `buildContent()`, `drawFinger()`, `AMBER` |
| `censorMotion.ts` | ЧИСТАЯ математика цензуры | swap-dance / row-shear / combo, `CENSOR_PRESETS`, jitter |
| **`censorConfig.ts`** | **ЧИСТЫЙ конфиг цензуры — источник правды для стенда И доски** | `DANCE_DEFAULT` (5/25/1/1), `DUST_FLICKER=false`, `DUST_TIME_SCALE=1/3`, `dustParams()`, `dustPoints()`; есть тест |
| `engine/censorSource.ts` | Pixi-извлечение силуэта фака | `buildFingerGrid(app,block)` (сетка) + `buildFingerDustPoints(app,step,cx,cy)` (облако точек) |
| `engine/censorField.ts` | императивный CPU-рендер по любой пиксель-сетке | держит рабочую сетку свапов; `update(t)` |
| `engine/censorGpu.ts` | GPU-цензура (кастомный Pixi-фильтр) | «remap» стейтлесс; «pingpong» = поле смещений с возвратом (ограничено) |
| `engine/censorParticles.ts` | Telegram-пыль | позиция/alpha частицы = чистая функция возраста; флаги `flicker`, `timeScale` |
| `ui/Card.ts` (скрытая карта) | живая пыль на реальной карте | `hiddenBg` + `ParticleField`-оверлей; крутит в `step`, `resting=false`, прячет при флипе |
| **`engine/sceneEngine.ts`** | **ОБЩАЯ ОБВЯЗКА СЦЕНЫ — база для любой игры со столом** | камера + ввод + драг + дроп-зоны + «подглядеть» + цикл и тени + экранный HUD; сцена даёт только `draggables`/`everyElement`/`homeOf`, прочее — швы |
| `ui/TopBar.ts` | канвасная верхняя панель (HTML в приложении не держим) | кнопки слева, статус справа; слой `chrome` вне камеры; ввод — через движок, как у карт |
| **`engine/kitScene.ts`** | **витрина ОДНОГО компонента на общей обвязке стола** — хост стори | реализует `SectionContext` + `add`/`extent`/`dispatch`; `rebuild()` БЕЗ пересоздания канваса; про Storybook не знает (зависимость односторонняя) |
| `engine/kitSceneKey.ts` | ключ пула витрин и его РАЗБОР обратно в опции | без Pixi → тестируемо в node; тест на обратимость обязателен (ключ уже один раз молча разъехался с разбором) |
| **`game/kit/*`** | **секции стенда как свободные функции над `SectionContext`** | `context` (контракт), `cardVariants`, `buttons`, `dropzones`, `dropIndicator`, `pieces`, `stacks`, `widgets`, `commandPort`, `markerIcons`. Один и тот же код рисует раздел песочницы и стори каталога |
| `engine/kitExtent.ts` | чистая математика витрины | `extentOf`/`fitZoom`; содержимое живёт в ПОЛОЖИТЕЛЬНОЙ четверти, (0,0) — левый верхний угол (как в песочнице) |
| `CanvasApp.reattach(host,w,h)` | перевесить ЖИВОЙ канвас в другой хост | без нового WebGL-контекста; ради переключения стори (браузер режет контексты на ~16) |
| **`src/stories/kit/cardArgs.ts`** | **ПОЛНАЯ карта опций карты** | `satisfies Record<keyof CardOptions, …>` → новая опция у `Card` РОНЯЕТ `tsc`, пока её не опишут. Единственное место, где «что у карты есть» собрано целиком |
| `src/stories/harness/*` | адаптер Storybook ↔ канвас | `canvasPool` (пул контекстов), `argApply` (живьём vs пересборка), `paramArgs` (мост `Param`↔`argTypes`), `CanvasStage` (React-хост), `kitPool` (пул на `globalThis` + HMR-dispose + дев-хук `__kit`) |
| `ui/OverlayPanel.ts` | канвасный ЭКРАН ФАЗЫ (меню/итог/пауза) | затемнение + заголовок + подпись + кнопки; `activeButtons()` — скрытая панель не ловит ввод |
| **`solitaire/tree.ts`** | геометрия Косынки: ОДНО дерево слотов на рендер и на дроп | доска фиксированного размера, под экран её вписывает камера; приём — `caps.drop.accept` из `solitaireRules` |
| `solitaire/scene.ts` | `SolitaireScene extends SceneEngine` | своего ввода/камеры/драга нет; домен — `canDrag`/`beginDrag`/`resolveDrop`/`onElementBlocked` |
| **`engine/panZoom.ts`** | приклеиваемый пан/зум для сцен БЕЗ своего движка (`/motion`) | `attachPanZoom(app, content, opts)`; сценам на `SceneEngine` не нужен — камера уже в базе |
| `engine/viewport.ts` | чистая математика камеры | x/y/zoom, clamp, инерция (fling), `state()` для скроллбаров |
| `engine/inputRouter.ts` | стейт-машина жестов | none/drag/pan/pinch/button/hover; домен — в колбэках |
| `ui/controls.ts` | декларативные контролы | `Configurable.params()` → `Stepper`(number)/`Toggle`(bool); `attachControls` |
| `censorDemo.ts` + `CensorDemo.tsx` | стенд `/motion` | всё в канвасе; секции = заголовок+контролы+карты; DOM = топбар+скроллбары |
| `docs/animation-levers.md` | дизайн-референс рычагов | уровни (движок/геймдизайнер/юзер), назначения, что забыли/перегибаем |

**Принцип, который держим:** контролы в канвасе сами ввод не слушают — их клики роутит
`InputRouter` (через `attachPanZoom` → `opts.buttons`), чтобы кнопки не спорили за pointer с паном.
