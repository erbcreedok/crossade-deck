# Рычаги анимации: уровни и назначение

Референс при проектировании настроек анимации/производительности. Заземлено на паттернах
mobile quality-tiers, Xbox/iOS accessibility (reduce-motion), веб `prefers-reduced-motion`.
Уже есть в движке: профиль `moderate`/`full`, один `shadowPass`, пружины, `idleGate`.

## 1. Три уровня контроля (кто выставляет значение)

| Уровень | Кто | Гранулярность | Пример |
|---|---|---|---|
| Движок / профиль | авто + пресет | грубая: `off / low / moderate / full` | есть `moderate`/`full`; нет авто-даунгрейда по FPS |
| Геймдизайнер / скоуп | создатель правил | абстрактный скоуп, НЕ слот | «фил» набора: пыль как рубашка скрытой карты, длительность флипа |
| Пользователь | игрок | оверрайд поверх дефолта | master reduce-motion + 2–3 тумблера + скорость |

Создателю игр — рычаги на уровне скоупа/пресета, не на слот. Никто не настраивает анимацию
покарточно; выбирается тема/пресет фила. `/motion` с параметр-слайдерами — dev-витрина, не shipping-UI (§5).

## 2. Рычаги по назначению

### A. Производительность (владелец дефолта — движок/профиль)
- FPS-кап (30/60/120) + авто-детект: уронил FPS → спусти профиль.
- Плотность/количество частиц пыли — единственный реальный перф-рычаг частиц (не size, не freq).
- Idle-анимации (дыхание на `full`) — первое, что режется.
- Shadow-pass, tilt/блик-пассы — вкл/выкл целыми проходами.
- Пружинная физика (springs) — симуляция каждый кадр; можно заменить мгновенным.

### B. Комфорт / доступность (владелец — пользователь, но honor OS)
- Master «reduce motion» — honor `prefers-reduced-motion` / iOS/Android. Пока нет — стандарт де-факто.
- Интенсивность тряски рядов / шейка — слайдер 0–100% (Halo: 0–100 screen shake).
- Тумблер мерцания/вспышек — TG-пыль мерцает, «сжечь» вспыхивает → фото-чувствительность.
- Отключение idle-движения (сенсорная перегрузка / ADHD-паттерн).

### C. Ощущение / тайминг (владелец — пользователь ИЛИ клиент-заказчик)
- Глобальный множитель скорости анимаций (есть `speed`) — «сделать быстрее».
- Пружинистость/дрожь вкл/выкл — stiffness/damping или тумблер spring→instant.
- Длительность флипа карты/стопки.

### D. Сочность / эстетика (владелец — движок `high`, opt-in на мощных)
- Тени на картах, блик при тильте вбок, hover-реакции под курсором.
- «3D-конь в 2D-слое», расчёт теней/бликов по позиции — будущий `ultra`.
- Аддитивно: дефолт задизайнен геймдизайнером, мощная машина получает больше.

## 3. Карта: анимация → рычаги → чей дефолт

| Анимация | Perf | Comfort | Feel | Уровень дефолта |
|---|---|---|---|---|
| Пыль (цензура) | плотность, FPS | вспышки, интенсивность | — | скоуп (рубашка) |
| Тряска рядов | вкл/выкл | интенсивность 0–100 | скорость | скоуп + юзер |
| Idle (дыхание) | режется первым | отключить | — | профиль |
| «Сжечь» | частицы | вспышка-флаг | скорость | скоуп |
| Флип карты/стопки | — | — | длительность, spring | скоуп + юзер |
| Драг / пружины | spring-симуляция | — | дрожь вкл/выкл | юзер (перф!) |
| Тени / блик / тильт | пассы вкл/выкл | — | — | профиль `high` |

## 4. Что забыли учесть (чеклист)

1. Master reduce-motion, читающий OS — бесплатно, стандарт, нет.
2. ~~Авто-профиль по FPS — нет автопонижения при просадке.~~ ✓ issue #8: бинарный тир `full`↔`reduced`
   на базе `CanvasApp` (`FpsMeter` в цикле + `nextTier` с гистерезисом 45/55fps, первый кадр после сна не
   сэмплируется). `reduced` = idle-заморозок (bob/пыль/тряска зон, как reduce-motion) + выключение
   shadow-пасса. Юзер-оверрайд `auto/full/reduced`. Индикатор FPS + сегмент + dev-«нагрузка» на `/motion`.
3. ~~Флаг вспышек/мерцания (фото-чувствительность) — TG-пыль + «сжечь» мигают.~~ ✓ issue #9:
   отдельный `reduceFlash` (auto/on/off, auto наследует `prefers-reduced-motion`) на базе `CanvasApp`;
   `flashOff = reduceMotion || reduceFlash` — reduce-motion надмножество. Гасит мерцание частиц и дрожь
   «сжечь» (Card/Piece), плавный расход остаётся. Тумблер «без вспышек» на стенде `/motion`.
4. Драг-режим = урезать анимацию именно во время драга («виснет драг»): пока тащишь — глушим фон.
5. Батарея/термал на мобиле — на low battery резать idle/частицы.
6. Плотность частиц как tier-рычаг, не юзер-слайдер (реальная цена — количество).

## 5. Где перегибаем (overthinking vs другие)

- Слайдер-на-параметр — dev-инструмент. В shipping: 1 пресет + master reduce-motion + 2–3 тумблера.
- Не строить покарточный/послотовый конфиг анимаций для геймдизайнера — избыточно, он выбирает пресет-скоуп.
- GPU vs CPU варианты пыли — в прод один (дешёвый), остальные оставить как dev-сравнение.

## 6. Рекомендуемый shipping-набор (минимум)

```
Профиль:   [ Авто | Низкий | Средний | Высокий ]   ← 80% юзеров трогают только это
Master:    [x] Уменьшить движение (по умолчанию = OS)
Тумблеры:  [ ] Тряска/шейк   [ ] Мерцание/вспышки   [ ] Пружинистость
Слайдер:   Скорость анимаций [====|----] 1.0x
```

Геймдизайнеру — отдельный конфиг-скоуп с семантическими дефолтами (не эти же слайдеры).
