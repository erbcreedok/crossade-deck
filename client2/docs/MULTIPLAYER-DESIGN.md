# Multiplayer — секция Storybook: N клиентов на одной странице

Дизайн-контракт. Написан 2026-08-03 после обсуждения с владельцем. Ветка `storybook`.
Рамка владельца: локальный мультиплеер как ДЕБАГ-интерфейс — Storybook поднимает N «клиентов»
на одной странице; действие в одном клиенте у остальных проигрывается «как будто сервер тронул».
Сервера нет и на этом этапе не будет, но всё строится так, чтобы реальный сокет (или другой
протокол) подключался заменой одной реализации, без правок клиента.

## Ключевая опора: шов уже существует

`game/crossade/net.ts` зависит не от colyseus.js, а от duck-типов:
`SendableRoom` (`send(type, message?)`) и `BindableRoom` (`onStateChange`/`onMessage`).
Это и есть транспорт-абстракция — форма colyseus-Room. Любой транспорт (in-memory мастер,
WebSocket, что угодно) реализует эти три метода, и сцена не знает разницы.
Прайор-арт — boardgame.io: транспорт `Local()` (клиенты на одной странице + in-memory master
с авторитетным состоянием) подменяется на `SocketIO()` без изменения клиента. Мы делаем то же.

## Решения владельца (2026-08-03)

1. **Сцена — новая минимальная**, не CrossadeScene: одна общая зона «стол» (все видят всё,
   класть и забирать может любой) + своя рука у каждого (владельцу лица, остальным рубашки).
   CrossadeScene подключить в секцию — возможный второй шаг, интерфейсы совпадут.
2. **Задержка доставки — сразу**: арг `latency`, тривиальный `setTimeout` вокруг доставки.
   Бесплатная проверка stale-echo-логики до реального сокета.
3. Кол-во игроков — арг Storybook, диапазон 2–6.

## Архитектура

```
Стори "Multiplayer/Table"
┌─────────────────────────────────────────────┐
│  LocalTableMaster — in-memory, авторитетный │   один на стори
│  state (plain-объекты формы схемы)          │
│  редьюсеры: сообщение → мутация → broadcast │
└──────┬──────────┬──────────┬──────────┬─────┘
   connect(sid)  …каждый connect() отдаёт клиента…
┌──────▼───┐ ┌────▼─────┐ ┌───▼──────┐ ┌──▼───────┐
│LocalRoom │ │LocalRoom │ │LocalRoom │ │LocalRoom │   реализуют SendableRoom+BindableRoom
├──────────┤ ├──────────┤ ├──────────┤ ├──────────┤
│ Scene A  │ │ Scene B  │ │ Scene C  │ │ Scene D  │   обычные сцены, о фейке не знают
└──────────┘ └──────────┘ └──────────┘ └──────────┘
```

- **`LocalTableMaster`** — чистый модуль, БЕЗ Pixi и React. Авторитетное состояние в форме
  duck-типов схемы (plain Array/Map подходят под `ForEachArray`/`ForEachMap` сами).
  `send()` любого клиента → редьюсер → мутация → `onStateChange` у ВСЕХ клиентов, включая
  автора (семантика Colyseus). Отсюда «у одного всё как есть, у остальных программатически» —
  само, без спецкода.
- **`LocalRoomClient`** — то, что получает сцена: `send`/`onStateChange`/`onMessage` +
  `sessionId`. Доставка в обе стороны — через `latency` (0 по умолчанию).
- **Протокол** — минимальный поднабор, имена и формы сообщений РОВНО серверные
  (`server/src/messages/*`): положить на стол / взять со стола / порядок руки. Не изобретать
  свои имена — иначе подключение реального сервера станет переводом, а не заменой транспорта.
- **Стори**: арг `players` (2–6) → грид из N канвас-хостов; арг `latency`. Один мастер на
  экземпляр стори, `destroy` сцен и мастера при размонтировании.

## Где это в коде (реализовано 2026-08-03)

- `src/game/multiplayer/localTable.ts` (+ тест) — мастер и клиенты; тест гоняет клиентов через
  НАСТОЯЩИЙ `bindRoom`/`snapshotFrom` — сломается форма состояния, сломается тест.
- `src/game/multiplayer/tree.ts` (+ тест) — дерево слотов дебаг-стола (play-грид + рука + места).
- `src/game/multiplayer/scene.ts` — сцена; усечённый `CrossadeScene`, механика та же.
- `src/game/multiplayer/pending.ts` (+ тест) — ожидание одобрения сервера: дроп в другую зону НЕ
  отпускает карту домой — она висит в точке ПАЛЬЦА поднятой (дыхание сохраняется), затянувшийся
  запрос (>0.4 c) получает индикатор: спиннер-дугу В ТОЧКЕ КАСАНИЯ на карте + лёгкий оверлей-
  притемнение по её контуру (оба — дети node.root, наследуют трансформы карты); отказ/молчание
  (5 c) — «стоп»-покачивание и домой. Без этого при заметной latency карта успевала долететь до
  руки и лишь потом прыгала в зону.
- `src/stories/multiplayer/` — секция `Mechanics/Multiplayer` (стори + React-хост грида клиентов).
- Дев-хук: `globalThis.__mp[sessionId]` → сцена клиента, `testHooks()` — экранная геометрия.

## Осознанные trade-offs

- **Редьюсеры мастера дублируют часть серверных правил.** `@colyseus/schema` в браузер не
  тащим. Сейчас — минимальный поднабор чистыми функциями с тестами; shared-пакет правил —
  только когда дублирование реально заболит, не вперёд потребности.
- **Мастер — не сервер.** Он не проверяет права/фазы сверх минимума, нужного дебаг-столу.
  Его работа — семантика доставки (авторитетность, broadcast, порядок сообщений, задержка),
  а не полнота правил.
