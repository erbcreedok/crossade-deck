# Сценарий: наборы, скины и коробки (видение владельца)

Записано со слов владельца 2026-08-07. Это **эталон поведения**, воспроизводимый на этапе 5.
Идентификаторы английские, прозой — по-русски. Каждый пункт «Тогда» обязан стать тестом.

Слово «колода» здесь не употребляется: оно значило четыре вещи сразу. Вместо него — **набор**
(`ElementSet`), **скин** (`Skin`), **коробка** (`Box`) и **стопка** (роль зоны).

## Обстановка

```ts
standard52 = ElementSet { fields: { suit, rank, color }, size: card,  flip: back }
standard36 = ElementSet { fields: { suit, rank, color }, size: card,  flip: back }
uno        = ElementSet { fields: { color, rank },       size: bigger, flip: back }
chipSet    = ElementSet { fields: { denom },             size: chip,  flip: same }
```

> `size` в строках выше — СОКРАЩЕНИЕ обстановки: у набора, где все записи одного размера, он один на
> всех. Правило же — размер объявлен у КАЖДОЙ записи (§G, п.103): король выше пешки внутри одного
> набора. На элементе `size` — дефолт, который экземпляр может переписать через `bounds`
> (`CANONS.md`, § «Поля: типы, единицы и класс наследования»).

```ts
box:d1 = Box { set: standard52, skin: classic }
box:d2 = Box { set: standard52, skin: gilded  }

stock@d1 = Zone { layout: deckStack, grab: top, box: "d1", occupied: merge }
hand@u1  = Zone { layout: fan, grab: one, hot: phantom, owner: "u1" }   // box НЕТ
```

Механика не карточная: `chipSet` и `chessSet` проходят все сценарии ниже без единой правки — меняются
только имена полей.

## A. Опустевшая коробка

- **Дано**: все карты из `stock@d1` розданы.
- **Тогда**: стопка **не исчезает**. Тот же элемент с `children: []`, его так же можно таскать (если
  коробку вообще разрешено таскать) и в него так же можно класть карты.
- **Тогда**: отдельной сущности-якоря НЕ появляется — это вид, а не второй объект.
- **Тогда**: `target.top` у неё — **ничто**, и стянуть с неё нечего: `grab` отдаёт пустой груз,
  перетаскивание не начинается. Тащится САМА коробка, если она `Draggable`.
- **Тогда**: правило, сравнивающее что-либо с `target.top`, даёт **`deny`** — отказ выглядит как
  молчание, а не как ошибка. «Пустая принимает туза» пишется через `target.count`, он есть всегда.
- **Когда** зову «вернуть родные».
- **Тогда**: возвращаются ровно карты этой коробки — `{ eq: ["el.box", "target.box"] }`, включая
  лежащие в чужих руках, если игра это разрешает.

## B. Две коробки одного набора

- **Дано**: `box:d1` (classic) и `box:d2` (gilded), набор у обеих `standard52`.
- **Тогда**: пятёрка пик из первой и пятёрка пик из второй — **два разных нода**, никак не связанные.
  Равенство по номиналу — правило конкретной игры, а не свойство кита.
- **Тогда**: `id` у них разный и **непрозрачный**. Движок не выводит из идентификатора ни масти, ни
  принадлежности коробке — для этого есть поле.

## C. Слияние дропом

- **Дано**: два игрока вынесли на стол по коробке `standard52`.
- **Когда** роняю одну стопку на другую.
- **Тогда**: получается одна стопка на 104 карты — это `occupied: { use: "merge" }`, а не новая
  механика.
- **Тогда** при `absorb: true`: старая сущность-коробка умирает.
- **Тогда** при `absorb: false`: старая коробка **остаётся якорем** на своей позиции, и её родные
  карты можно отозвать в любой момент.
- **Тогда** в обоих случаях: каждая карта сохраняет **родную рубашку**. Автоматического рескина под
  один вид НЕ происходит.

## D. Сверка: 52 → 36

- **Дано**: меняю набор коробки со `standard52` на `standard36`.
- **Тогда**: срабатывает **сверка** (`reconcile`). Дефолт разрешает только тот же набор
  (`strict`); шире — расширяет дизайнер, а не учтённое ЗАПРЕЩЕНО, а не «как-нибудь».
- **Тогда** при `drop`: шестнадцать лишних карт исчезают — в новом наборе их физически нет.
- **Тогда** при `ghost` (игра запрещает убирать со стола): двойка крестей становится призрачной
  прозрачной картой со своим скином и остаётся лежать где лежала.
- **Тогда** при `keep`: лишние остаются картами старого набора, помеченными **незаменяемыми**.
- **Тогда** во всех случаях лишние **в чужих руках** обрабатываются тем же пресетом, а не особым
  способом.

## E. Сверка: 36 → 52

- **Дано**: меняю набор со `standard36` на `standard52`.
- **Тогда**: недостающие шестнадцать карт **добавляются в стопку**.
- **Тогда**: уже розданные тридцать шесть **не исчезают и не сбрасываются**. Они остаются
  полноценными элементами НОВОГО набора — просто со **старым скином**.
- **Тогда**: значит скин это **значение на элементе**, а не ссылка на общий слой. Иначе этот пункт
  невыразим.

## F. Рескин на месте

- **Дано**: играю в косынку, захотел другую рубашку и другие лица.
- **Когда** меняю в настройках или подменяю коробку той, что есть.
- **Тогда**: **все карты остаются на своих местах**. Ни одна не двигается, раскладка не
  пересчитывается как новая, пересдачи нет.
- **Дано**: песочница, игра уже идёт.
- **Когда** через контекстное меню меняю текущую коробку на свою.
- **Тогда**: **у всех** в руках карты становятся выбранной коробкой — решение авторитетное, едет в
  состояние.
- **Тогда**: это ВЫРОЖДЕННЫЙ случай сверки (отображение один-в-один, лишних и недостающих нет), а не
  отдельный механизм.
- **Дано**: строгий стендалон (классический дурак), инвентарь недоступен, коробка одна на сессию.
- **Тогда**: рескин всё равно доступен — он не трогает сущности.

## G. Смешанные размеры в одной руке

- **Дано**: в `hand@u1` лежат карта `standard52` и карта `uno`.
- **Тогда**: они разного размера на одной оси, и это НОРМА. Веер меряет каждого ребёнка по его
  собственному следу.
- **Дано**: шахматный набор.
- **Тогда**: король выше пешки внутри ОДНОГО набора — значит размер объявлен у каждой записи, а не у
  набора целиком.

## H. Сортировка

- **Дано**: рука из карт `standard52`.
- **Тогда**: в меню сортировок есть масть, ранг, цвет — ровно те поля, что объявлены в наборе.
- **Дано**: рука из карт `munchkinDoors`.
- **Тогда**: в меню тип, раса, класс, уровень, имя. Движок **не изменился ни на строку**: компаратор
  ключуется ТИПОМ поля (`ordered` · `number` · `text` · `flag`), а не его именем.
- **Дано**: стопка фишек.
- **Тогда**: сортировка по номиналу (`number`), строки «по масти» НЕТ — поля нет.
- **Тогда**: «сначала по масти, потом по рангу» — это список полей, а не новый компаратор;
  направление — параметр; `text` берёт коллатор текущей локали.
- **Тогда**: «сначала козыри» в меню НЕ появляется — козырь свойство раздачи, а не элемента. Такая
  сортировка регистрируется потребителем кита.

## I. Доступность

- **Дано**: пользователь включил в личном конфиге четырёхцветные масти.
- **Тогда**: `standard52` рисуется альтернативными лицами; `uno` и `chipSet` не меняются — у них
  такой альтернативы нет, и переключатель для них не предлагается.
- **Тогда**: настройка **локальна**, в состояние не едет. Двое за одним столом видят разное, и это
  нормально: это доступность, а не правило игры — как motion-reduce и тёмная тема.

## Что из этого следует для модели

1. **Три сущности вместо одной**: набор (что бывает) · скин (как выглядит) · коробка (чей экземпляр).
   Зона в это семейство не входит — она из колонки «где лежит» и описана разбором контейнера.
2. **Набор — точка рождения элемента ЦЕЛИКОМ**: способности, поля, размер, скин по умолчанию. Не
   таблица значений.
3. **Скин — значение на элементе.** Пункты E и C по отдельности этого требуют; вместе они не
   оставляют выбора.
4. **Два глагола, не путать**: рескин переписывает скин, сверка и слияние — не трогают.
5. **Слияние — это `occupied`**, а не своя механика. Замена и слияние — один механизм с двумя
   спусковыми крючками.
6. **Сортировка масштабируется данными**, потому что компаратор ключуется типом. Новый вид элементов
   стоит ноль строк движка; новый вид ПРАВИЛ — регистрация у того, чьи это правила.
7. **Схема полей набора и есть словарь путей** для `AcceptRule`: `el.values.X` легален ровно тогда,
   когда `X` объявлен. Изобретать словарь отдельно не нужно.
8. **`id` непрозрачен** — сторож-скан на `split`/`startsWith`/сравнение с литералом.
