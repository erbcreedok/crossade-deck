# Сценарий: приём в свою и чужую руку (видение владельца)

Записано со слов владельца 2026-08-07. Это **эталон поведения**, который мы воспроизводим на этапах
3–4. Идентификаторы английские, прозой — по-русски. Каждый пункт «Тогда» обязан стать тестом.

## Обстановка

- Две руки на борде: `hand@me` и `hand@p2`. Обе **открыты** и доступны **по запросу**.
- В каждой по 5 карт.
- На столе лежат: одна карта и одна фишка.
- Правило обеих рук: принимать только карты; в СВОЮ — сразу, в ЧУЖУЮ — с согласия владельца.

```ts
// hand accept rule: cards only; my own hand needs no consent, someone else's does
accept: {
  and: [
    { has: "card" },
    { or: [ { eq: ["actor.seat", "target.owner"] }, { ask: "owner-consent" } ] },
  ],
}
```

## A. Карта → МОЯ рука

- **Дано**: тащу карту со стола, держу над своей рукой, не отпускаю.
- **Тогда** (ховер): карты в руке **расступаются**, освобождая место будущему соседу — ровно в той
  позиции, на которую указывает палец.
- **Когда** отпускаю.
- **Тогда**: карта падает **в указанную позицию** (не в конец руки).

## B. Фишка → МОЯ рука

- **Дано**: тащу фишку, вожу над своей рукой.
- **Тогда** (ховер): рука и её содержимое **не реагируют никак**. Ни зазора, ни подсветки, ни рамки.
- **Когда** отпускаю над рукой.
- **Тогда**: фишка улетает **туда, откуда её подняли**.

> **Отказ — это молчание.** Красной подсветки не существует. Отсутствие реакции и есть ответ.

## C. Карта → рука ЮЗЕРА 2 (по запросу)

- **Дано**: тащу карту, держу над чужой рукой.
- **Тогда** (ховер): её карты **тоже расступаются** — превью работает, хотя нужно согласие.
- **Когда** отпускаю.
- **Тогда**: карта **висит в idle-состоянии** у цели, с индикатором из **трёх точек** — не спиннер:
  точки читаются как «ждём решения человека», спиннер — как «идёт загрузка».
- **Когда** владелец согласился.
- **Тогда**: карта падает **в ту позицию, которую я указал** при отпускании.
- **Когда** владелец отказался (или таймаут).
- **Тогда**: карта улетает **туда, откуда её подняли**.

## D. Фишка → рука ЮЗЕРА 2

- **Тогда** (ховер): чужая рука **не реагирует**.
- **Когда** отпускаю.
- **Тогда**: **никаких механик** — запрос не отправляется, ничего не «висит»; фишка возвращается
  в исходное место.

## E. Пока карта висит: отмена, локи, соперничество

- **Ожидание — это ЗАПИСЬ, а не флаг на карте.** `PendingRequest { id, els, from{parent,after},
  to{parent,after}, actor, resolver, deadline }` живёт в общем состоянии. Просить можно о ПАЧКЕ:
  груз перетаскивания — список (`DragPayload.els`, 1..M), а не один элемент. Оба конца интеракции
  читают её и метятся: карта — тремя точками, зона-цель — состоянием `pending`.
- **Заперт ТОЛЬКО элемент.** Карту в ожидании не может взять никто, включая просителя.
- **Цель НЕ заперта**: владелец руки продолжает играть, класть и брать свои карты.
- **Источник НЕ заперт**: стол живёт дальше.
- **Отменить может только проситель** («передумал») — это не взятие, а отзыв запроса.
- **Намерение привязано к СОСЕДУ, а не к индексу** (`after: cardId`): пока владелец переставлял свои
  карты, абсолютный индекс уже врёт. Тот же принцип, что «стопка ключуется идентичностью, не
  индексом».
- **Правило считается ДВАЖДЫ** — при отпускании и ещё раз при коммите. Согласие владельца не
  отменяет правил: рука успела заполниться / карта стала `eaten` / место ушло — возврат домой.
- **Пять входов, ровно два исхода**: согласие · отказ · отзыв · таймаут · правило сломалось →
  **коммит** или **возврат**. Третьего состояния у запроса нет.
- **Гонки решает порядок сообщений**, а не логика: отзыв и согласие пришли одновременно — выигрывает
  первое дошедшее (сервер обрабатывает по одному, как `take_card` в client1).
- **Возврат домой — best-effort**: исходное место могли занять; тогда ближайшее свободное, затем
  дефолт контейнера. Карта не имеет права застрять.
- **Лимит открытых запросов** — параметр записи резолвера (`maxOpen`), иначе один игрок завалит
  другого двадцатью просьбами.
- **Кто и как спрашивает согласие — дело ПОТРЕБИТЕЛЯ кита.** Кит даёт состояние `pending` и контракт
  резолвера; панель «принять / отклонить» рисует Песочница или игра, скорее всего в HUD.

## Что из этого следует для модели

1. **Три вердикта — три разных ховера**: `allow` → превью-расступание; `ask` → превью **тоже**
   (форма хода легальна, не хватает только власти); `deny` → полное молчание.
   Превью привязано к `allow ∪ ask`, ожидание — только к `ask`.
2. **Намерение сохраняется через ожидание**: в pending-записи лежат `target` + **индекс слота** +
   `origin` (родитель и индекс). Согласие кладёт карту в тот же индекс; отказ возвращает в origin.
3. **Расступание — не механика, а РАСКЛАДКА `n+m` с фантомами.** Контейнер под пальцем
   раскладывается на `n+m` детей, фантомы стоят на `indexAt(палец)`, пружины разводят соседей сами.
   Именно поэтому раскладка обязана отвечать в обе стороны (`place` и `indexAt`), а именованной
   механики `makeRoom` не существует. Сколько зазоров показывать — параметр записи `hot`
   (`maxGaps`), и это НЕ вместимость зоны: вместимость отказывает, `maxGaps` только рисует.
4. **Ожидание ≠ загрузка**: индикатор ожидания решения — три точки; спиннер зарезервирован за сетью.
5. **Правило руки реляционно**: `actor.seat` сравнивается с `target.owner` — без сравнений в DSL
   этот сценарий не выражается.
6. **Обводка зоны**: `rest | armed | hot | pending`. Состояния «отказ» НЕТ — отказ выглядит как
   `rest`.
7. Пока карта висит в pending, зазор в чужой руке **остаётся открытым** — и это не отдельное
   решение, а следствие п. 3: фантом привязан к `after` из `PendingRequest`, значит держится ровно
   столько, сколько живёт запись.
