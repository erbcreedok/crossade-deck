# Дизайн: HUD, меры, UI-элементы, ввод текста

Спроектировано, не построено (этап 3 для контролов, 4 для HUD).

## HUD — второй корень

Разница между корнями ровно одна: камера трансформирует `CanvasRoot` и не трогает `HudRoot`. Поля
`anchor` не существует; переезд элемента HUD↔холст — смена родителя.

HUD отдаёт камере **safe-area RECT** и больше ничего. Доки бывают по всем краям, поэтому область
безопасности прямоугольник, а не скаляр `insetTop`.

## Мера: `unit` существует ровно у HUD

У стола универсальной меры НЕТ — числа в мировых координатах плюс камера (см.
`docs/design/camera.md`). У HUD камеры нет, поэтому мера нужна: **эталонный квадрат, заданный ДОЛЕЙ
ЭКРАНА** (например 25% меньшей стороны), от которого кратно считаются размеры HUD-элементов.

Без него каждый HUD-элемент заводит свою долю: один `0.2` высоты экрана с потолком и полом `48…120`
px, второй свою, третий свою — вот это и есть дыра.

`unit` **локален как камера**, в состояние не едет: истина — размеры в юнитах, пиксели у каждого
зрителя свои. Пользователь может переопределить эталон (крупные иконки) — это единственная ручка
доступности такого рода.

`boxFit` — про другое: как коробка С ПОДПИСЬЮ выбирает свой габарит. Он вынесен из кнопки специально,
чтобы дроп-зона и шильдик не завели свои слегка другие правила.

**Свет и `z` у HUD**: свет в кадре `viewer` (у холста — `world`); `z` в единицах СТОЛА, камера
масштабирует результат, и цепочка `zCompose` у `HudRoot` своя — иначе кнопка прыгала бы в тени при
отъезде камеры.

## UI-элементы — это ЭЛЕМЕНТЫ. Второго мира нет

Кнопки, тексты, иконки, переключатели, меню, индикаторы, поля ввода — тот же элемент с теми же
атомами. Тень, `z`, `angle`, `orientation`, драг НЕ появляются заново, они приходят с базы. Нужна
перетаскиваемая кнопка — добавил `Placeable + Draggable`, спорить нечему. Место обитания — тоже не
свойство, а РОДИТЕЛЬСТВО.

Своего у контролов ровно четыре атома (`Valued`, `Labeled`, `Actionable`, `Focusable`). Сборки:

```
Text = Labeled · Icon = визуал · Button = Labeled + Actionable · Toggle = Button + Valued
Menu = Container + Oriented · Indicator = Valued БЕЗ Actionable (три точки из hand-accept)
Input = Labeled + Valued<string> + Focusable · RadioGroup/Slider = Container + Valued
```

**Контрол не меняет состояние — он испускает НАМЕРЕНИЕ** (`action` — ссылка в реестр интентов);
локально оно или едет по проводу, решает потребитель кита. Кит не знает про ход и знать не должен.

Четыре следствия:
- **`disabled` ЗАПРЕЩЁН** — это ровно отрицание. Серая кнопка = `Actionable` отсутствует статически
  или его не выдал `caps(el, ctx)`; серость — СЛЕДСТВИЕ. Иначе неизбежно появится «`disabled: false`,
  но `caps` не даёт», и правого не будет.
- **`label` несёт ГОТОВЫЙ текст**, и кит не спрашивает, откуда он. Ответственность кита одна:
  пережить любую длину. Стори кнопки проверяются подставленной длинной строкой — немецкий длиннее
  русского, — и ширина меряется в ПИКСЕЛЯХ, а не в символах.
- **Контекстное меню на повёрнутом месте** — это `orientation: "viewer"`, терминатор цепочки углов.
  Отдельной «UI-камеры» не нужно.
- **Кнопки, тексты и меню не заводят своих теней и своих текстовых обёрток** — общий фундамент
  визуала, см. `CANONS.md` §4.

## Ввод текста — порт ХОСТА, а не DOM поверх канваса

DOM-инпут не повернулся бы в цепочке углов, не отбросил бы тень от единственного света, не встал бы в
`zCompose` — то есть выпал бы из всех законов сразу.

Шов проходит по трём слоям, платформозависим только верхний:
- `TextInputPort { open, close }` + события (`textChanged`, `selectionChanged`, `composition`) —
  записи реестра: `web` (скрытый input как ПРИЁМНИК событий) · `native` · `fake` (тесты и каталог,
  печатает из аргов) · `prompt` (честная деградация).
- Ниже — чистый `TextEditor { value, selection }`, тестируемый headless.
- Ещё ниже — обычная канвасная отрисовка.

**Выделение не теряется**: приёмник держит авторитетные строку и `selectionStart/End`, а канвас по
метрикам глифов (они и так нужны `boxFit`) находит индекс под пальцем и пишет обратно. Теряется
системное автозаполнение — для кода комнаты и ника это неважно, форма логина живёт в React-меню, а не
на столе.

Четыре грабли, записанные заранее:
- `focus()` ТОЛЬКО внутри обработчика жеста, иначе мобильная клавиатура не поднимется.
- Приёмник стоит В ТОЧКЕ КАРЕТКИ, 1×1, `opacity: 0`. За экраном — прыжок вьюпорта на iOS и промах
  окна кандидатов IME.
- `keyboard` — ПОЛЕ спеки, а не догадка (код комнаты → `numeric`).
- Мигание каретки — непрерывная анимация, обязана быть в idle-гейте.
