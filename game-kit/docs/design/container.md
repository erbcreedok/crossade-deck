# Дизайн: контейнер, зона, приём

Спроектировано, построено частично (`core/atoms/container.ts`, `core/atoms/layouts.ts` — `layout`,
`children`, раскладка). Всё остальное ниже — этап 3.5. Законы, действующие всегда, — в `CANONS.md`.

## Контейнер он же ЗОНА

Зона — это элемент: `Node + Bounded + Transformable + Container + Acceptor (+ Surfaced)`. Отдельного
`ZoneSpec` нет. Контейнер — полноценная фигура: drag/flip/selection/тень применимы к целому.

**Слот — АДРЕС, а не элемент.** Шахматная доска — ОДИН контейнер с сеткой, не 64 сущности: клетка не
имеет идентичности, она координата. Иначе пришлось бы держать в состоянии и гонять по проводу 64
пустых элемента — плату за то, чего нет. Форма адреса задаётся РАСКЛАДКОЙ: у сетки координата (`e4`),
у упорядоченной — СОСЕД (`after: cardId`, устойчив к чужому реордеру), у кучи — никакой. Клетке нужна
своя жизнь — вкладывается контейнер ребёнком, рекурсия уже разрешена.

```ts
Container {
  layout:    RegistryRef      // place + indexAt + cast + settle
  hot?:      RegistryRef      // ответ под пальцем; НЕТ ПОЛЯ = молчит
  grab?:     RegistryRef      // one | top | above; НЕТ ПОЛЯ = ничего не взять
  intent?:   RegistryRef      // как читается жест (свайп по стопке = тасовка)
  occupied?: RegistryRef      // что станет с тем, кто уже в слоте
  keeps?:    Capability[]     // способности детей, действующие внутри; НЕТ ПОЛЯ = все
  facing?:   { own, others }  // docs/design/transaction.md
  children:  ElementRef[]     // СОСТОЯНИЕ, не спека
}
```

`cast` — не поле контейнера, а часть записи раскладки: кто отбрасывает тень, знает тот, кто
расставил. `clamp` — тоже не поле, а параметр записи свободной раскладки (у четырёх раскладок из пяти
он не имеет смысла). `interactive` не существует — это было одно из четырёх имён `grab`.

## Раскладка — контракт из ДВУХ направлений

`place(i, n, ctx) → pose` и `indexAt(point, n, ctx) → i`. Обратное нужно потому, что только раскладка
знает геометрию: веер отвечает иначе, чем ряд.

Плюс `cast: "group" | "each"` — кто отбрасывает тень (`deckStack` → group, `fan`/`row`/`grid` → each;
отцепленный ребёнок кастит сам автоматически, он уже вне контейнера).

**Толщина стопки — раскладка, НЕ `z`** (сторож): положил карту в стопку — тень не шелохнулась.
Раскладке вообще запрещено писать `z`, см. `CANONS.md`.

**Стейтов-диффов НЕТ.** Дети живут в СОСТОЯНИИ, конфиг — в СПЕКЕ, поэтому «стопка ↔ веер» это
подмена ссылки `layout`: детей не тронули, спрайты ключуются идентичностью, пружины доигрывают
по-настоящему. Мини-система наследования с вопросами «что сливается, что заменяется» не понадобилась
ни для чего.

**Реестра «механик» тоже нет**: `liftAbove` / `splitOnCenterDrag` / «целое или ребёнок» /
`interactive` были четырьмя именами одного `grab`, а `makeRoom` — фантомами раскладки.

## Расступание — раскладка `n+m` с ФАНТОМАМИ

Не механика и не анимация. Груз перетаскивания — СПИСОК (`DragPayload.els`, 1..M), контейнер под
пальцем раскладывается на `n+m`, фантомы стоят на `indexAt(палец)`, пружины разводят соседей сами.

Отсюда СЛЕДУЕТ (а не решается отдельно), что зазор остаётся открытым, пока запрос висит: фантом
привязан к `after` из `PendingRequest`.

## `hot` — ответ под пальцем

Записи: `phantom` (рука, ряд, веер) · `lift` (стопка-цель поднимается и растёт, соседи отступают) ·
`arm` (только обводка слота) · `none` (куча сброса). Параметры там же: `{ maxGaps: 3, over: "badge" }`
— три зазора честно, дальше плашкой «+7»; лимит НЕ константа.

**Вместимость и `maxGaps` — разные вещи**: первое ПРАВИЛО (`{ lt: ["target.count", 10] }`, отказ),
второе ПОКАЗ. Зона может принять двадцать и рисовать три.

## `grab` — один вопрос: что уходит из-под пальца

`one` · `top` · `above`. Отдельного `split` НЕТ: «оторвать подстопку» и «поднять фишки, лежащие
сверху» — одно и то же взятие. Разница живёт в двух других местах, и там ей честнее:
- **как груз выглядит в полёте** (`DragPayload.carry`, по умолчанию наследует раскладку ИСТОЧНИКА —
  подстопка летит пачкой, фишки стопкой, веер веером, объявлять нечего);
- **что цель делает с пачкой** (`occupied`/`accept` ЦЕЛИ, не жест источника).

**Два уровня драга не путать:** `Container.grab` — что уходит, когда трогают РЕБЁНКА;
`Placeable + Draggable` у самого контейнера — уходит контейнер из своего родителя. «Унести контент,
слот остаётся» и «унести вместе со слотом» — разные уровни, а не два значения одного поля.

**Ребёнок без `grab` жест не съедает**: хит-тест идёт вверх по дереву и сам отдаёт его родителю —
сквозняк СЛЕДУЕТ, а не объявляется.

**У пустой стопки `grab` отдаёт пустой груз** — перетаскивание не начинается. Якорь опустевшей
коробки таскается как САМА коробка (если она `Draggable`), а не как её верхняя карта.

## `Grip` — предпочтительный маршрут к контейнеру

Возможность обязана быть ВИДНА: долгое зажатие — невидимая аффорданса, игрок её угадывает. `Grip {}`
— обычный ребёнок, чьи жесты адресованы родителю (драг целого, контекстное меню зоны); раскладка
резервирует ему место (ушко, корешок, край подноса) — не под стопкой, иначе его нечем нажать.

Три легальных маршрута, выбирает дизайнер: ручка (видна) · сквозняк по незакрытому полю (наполовину)
· эскалация жеста hold→целое (не видна — только ДОБАВКОЙ к первым двум, никогда единственным путём).

## `occupied` и `keeps`

**`occupied`** — что станет с тем, кто уже в слоте: `capture{to}` · `merge` · `swap` · `reject`. Это
НЕ дело `AcceptRule`: правило отвечает «пустить ли ЭТОГО» и молчит о судьбе жильца.

**`keeps`** — какие способности ребёнка действуют внутри (`discard: keeps: ["drag"]` — вынести можно,
вертеть на месте нельзя). Форма как у `bounds`: нет поля — разрешено всё, есть — сужение.
`allow_manual_flip: false` был бы флагом-отрицанием.

## `AcceptRule` — предикат-ДАННЫЕ

Сериализуемый DSL над caps+traits+values+state+ctx. Один механизм на приём-в-зону/контейнер/дроп,
едет в мультиплеер как данные. Пресеты правил — слой НАД движком (`acceptPresets`), контрол каталога
= селект по ним плюс крутилки.

**Четыре вида предиката, в порядке предпочтения:**
1. **`{ can: "hide" | "flip" | "drag" }`** — СПОСОБНОСТЬ. Самый устойчивый: не привязан к названию
   сорта. «В руку нельзя фишку» на самом деле значит «в руке держат то, у чего есть рубашка».
2. **`{ has: "card" }`** — ЧЕРТА, плоские данные. Честен, когда игра действительно про сорт (шахматы
   принимают шахматные фигуры, потому что это игра про них). Сахар, не протокол.
3. **`{ eq: [...] } / { lt: [...] }`** над путями (`el.values.rank`, `target.top.values.suit`) —
   ЗНАЧЕНИЕ. Реляционные правила карточных игр без этого не выражаются.
4. **`{ flag: "eaten" }`** — рантайм-СОСТОЯНИЕ. `eaten` — обычное состояние, читается тем же
   правилом; никакого `acceptEaten`.

**Легальные пути — те, что ОБЪЯВЛЕНЫ.** `el.values.X` легален ровно тогда, когда поле `X` объявлено в
наборе элемента; `el.box` и `el.set` легальны всегда. Валидатор спеки ловит `el.values.race` в игре,
где рас нет — словарь путей не нужно изобретать, он и есть схема полей набора.

**Вердикт трёхзначный, алгебра — трёхзначная логика** (`ask` = «неизвестно»):
- `and`: `deny` доминирует → иначе `ask`, если он есть → иначе `allow`.
- `or`: `allow` доминирует → иначе `ask`, если он есть → иначе `deny`.
- `not` над `ask` **запрещён валидатором**: «не спрашивать» смысла не имеет.

Отсюда «двойное ничего» падает само: `ask` стоит ВНУТРИ `and` после проверки формы, поэтому провал
формы гасит запрос — фишка над чужой рукой не порождает ни реакции, ни просьбы. **Превью** считает
вердикт, трактуя `ask` как `allow`; **запрос** рождается только если `ask` дожил до итога.

## У пустой стопки `target.top` — НИЧТО

Не фантом, не якорь, не пустой элемент-заглушка: верха нет, и стянуть с неё нечего. Три следствия, и
все три про то, чтобы «ничего» нигде не превратилось в «что-то»:
- **Сравнение с несуществующим путём — `deny`**, не `ask` и не ошибка. Отказ выглядит как молчание:
  зона не отвечает под пальцем, карта улетает домой.
- **«Пустая принимает туза» пишется через `target.count`**: `{ or: [ { eq: ["target.count", 0] },
  { eq: ["el.values.suit", "target.top.values.suit"] } ] }`. Счёт есть у любого контейнера всегда,
  поэтому фундаменты косынки выражаются без пятого вида предиката.
- **`grab` у пустой стопки отдаёт пустой груз** (см. выше).
