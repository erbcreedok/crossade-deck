# Ночной журнал решений — night/2026-08-11-client2-mechanics

Автономный забег: перенос механик client2 на атомарный движок. Владелец делегировал атомарные
решения на этой ветке (всё обратимо через git). Здесь — каждая догадка, её альтернатива и
насколько она обратима, для утреннего ревью. Спорное помечено ⚠.

Формат: **что решил** · альтернатива · обратимость.

---

## Приём (`AcceptRule`, `Acceptor`)

- **Эвалуатор — чистая функция над «субъектами», а не над `Node` напрямую.** `evaluate(rule, ctx)`
  где `ctx = { el: Subject, target: TargetSubject }`, `Subject = { caps, values, traits, box, set }`.
  Node-адаптер (`subjectOf`) строится отдельно. Альтернатива — гонять `Node` внутрь эвалуатора;
  отвергнута: тогда DSL нельзя проверить без сборки дерева. Обратимо (внутренняя форма).
- **`ask` порождается ТОЛЬКО явным `{ ask: rule }`-узлом** (внутреннее `deny` остаётся `deny`,
  иначе `ask`). ⚠ Дизайн не называет, какой примитив даёт `ask`; это догадка, вписанная в
  «превью трактует ask как allow, запрос рождается если ask дожил». Альтернатива — `ask` от
  нерезолвимого локально предиката. Обратимо (правка формы правила).
- **`values`/`traits`/`set` берутся из атомов, которых ещё нет** (`Valued`, `Owned`, наборы).
  Пока `subjectOf` читает что ЕСТЬ (caps, target.count/top), а отсутствующие источники → пусто →
  путь «не существует» → `deny` (ровно канон). Расширяется по мере постройки атомов. Обратимо.

## Политики контейнера (grab · occupied · keeps)

- **Каждая политика — ОТДЕЛЬНЫЙ атом над Container, а не опциональное поле Container.** Дизайн-док
  рисует их полями (`Container { hot?, grab?, ... }`), но построенный `Acceptor` уже сделал приём
  отдельным атомом, и система атомов пока не поддерживает опциональные поля (defaults требует все).
  Отдельные атомы (`Grabber{grab}`, `Displacer{occupied}`, `Keeper{keeps}`) канон-консистентнее
  («атом с одним законом») и разблокируют без правки defineAtom. Обратимо (можно слить в поля позже).
- **Дефолты:** Grabber `one` (берём тронутого), Displacer `reject` (не затирать), Keeper `[]`
  (присутствие с пустым = закрыто; ОТКРЫТО = отсутствие атома). Присутствие атома = opt-in,
  отсутствие = выключено (grab не съедает жест, keeps разрешает всё, occupied reject). Обратимо.
- **Имена атомов:** `Grabber`/`Displacer`/`Keeper` (-er к политике), по образцу `Acceptor`. ⚠ Спорно
  — владелец может захотеть поля на Container вместо. Обратимо (переименование/слияние).
- **occupied — записи-функции как у layout** (reject/swap/merge параметров нет, `capture(to)` печёт
  аргумент). `resolve()` без контекста. Обратимо.

## Flippable (переворот карты)

- **Какое ЛИЦО показать — чистая функция `shownFace(node, faceUp)`, а СТОРОНА (верх/низ) не
  хранится в атоме, а передаётся.** Альтернатива — держать `faceUp` полем атома. Сторона — рантайм-
  состояние партии (карту переворачивают в игре), а `Flippable` описывает КАК связан оборот с
  фронтом (спецификация), а не текущее положение. Так атом чист и сериализуем. Обратимо.
- **Четыре отношения оборота к фронту** (`back`/`same`/`mirror`/`alt`) — ⚠ была догадка, и владелец
  её ОТКЛОНИЛ. ОТМЕНЕНО (коммит «Flippable по уму»): свёрнуто в ОДНО поле `back` (поверхность
  изнанки). Причина: `back` и `alt` рендерятся одинаково, `mirror` художник не рисует, `same` = пустой
  `back`. `shownFace`/`Face` → `shownSurface`, возвращает саму поверхность. Урок: чужие «режимы» из
  клиент2 не переносить дословно — оставлять только то, что меняет пиксель.
- **Пустой `back` падает на фронт, а не бланчит** (`flip.back || front`). Переворот никогда не
  показывает пустоту: не назвал рубашку — видишь перед. Альтернатива — ошибка/пустой surface.
  Выбрано «мягко»: полу-настроенная карта играбельна. Обратимо (заменить на гвард). СОХРАНЕНО при упрощении.
- **`axis` (x/y)** — было поле оси переворота. ОТМЕНЕНО вместе с `reverse`: его читал только `mirror`,
  которого больше нет, а выбор поверхности от оси не зависит. Спекулятивное поле, что никто не читает
  (как `fit`/`align` в истории Surfaced) — убрано. Вернётся отдельным полем, если появится аниматор.

## Tiltable (тап карты)

- **Наклон = ДИСКРЕТНЫЕ упоры угла, а свободный спин это уже `Transformable.angle`.** Отдельного
  «Spinnable» нет: любой угол — это просто запись в angle (уже композитится по цепочке, тесты
  transformable t10/t12). Атом нужен только там, где углов КОНЕЧНЫЙ набор (стоит/тап). Обратимо.
- **Текущий упор — рантайм-индекс, передаётся; атом хранит только `stops`+`wrap`.** Как faceUp у
  Flippable: спецификация отдельно от состояния партии. Сериализуемо. Обратимо.
- **Дефолт `[0, 90]`, `wrap:true`** — самый частый кейс (untapped/tapped как в MTG, тап-тап
  распрямляет). ⚠ Догадка по клиент2. Обратимо.
- **Out-of-range индекс КЛАМПИТСЯ в список, не бросает и не undefined-ит** (`tiltAngle`). Тап
  никогда не наводит узел в никуда. Альтернатива — гвард/модуло. Выбран мягкий кламп. Обратимо.
- **`nextTilt` без Tiltable возвращает индекс как есть (не 0)** — нет упоров, нечему двигаться,
  состояние рантайма не трогаем. Обратимо.

## Actions (контекстное меню)

- **Действия НЕ хранятся на узле — они ВЫТЕКАЮТ из способностей.** Нет атома `Actionable`.
  `actionsOf(node)` = все зарегистрированные действия, чью cap узел несёт. Так карта не может
  рекламировать flip, которого не умеет (нет дублирования спецификации). ⚠ Спорно — владелец может
  захотеть на узле явный список/подавление отдельных глаголов. Обратимо (добавить атом-оверрайд).
- **Действие — запись реестра `{label, requires}`**, как layout/head/surface. Реестр решает, что
  существует; узел решает, что из этого доступно. `installStockActions`: flip→Flippable, tap→Tiltable,
  drag→Draggable, focus→Focusable. Consumer добавляет свои. Обратимо.
- **Порядок — порядок РЕГИСТРАЦИИ** (Map insertion order), не порядок атомов на узле. Стабильно и
  предсказуемо для меню. Альтернатива — сортировка по label. Обратимо.
- **`label` уже написан в записи** (кит не носит слов игрока — но реестр заполняет consumer своими
  словами, это его строки, не строки кита). Консистентно с каноном «строки приходят готовыми».

## Grippable (кто может поднять)

- **Права-близнец приватности, ТОЧНО зеркалит `visibleTo`.** Приватность режет что место видит,
  грип — что двигает. Тот же обход `chainOf`, тот же рез поддерева, та же семантика пустого списка
  (`by:[]` = заперто всем). Один закон в двух проекциях — консистентно и дёшево держать. Обратимо.
- **Нет реопена изнутри:** карта `by:[south]` внутри руки `by:[north]` заперта ОБОИМ. Рез предка
  выше по цепочке главенствует — карта в чужой руке не становится своей от собственной метки. Это
  то же свойство, что «публичный ребёнок в приватном контейнере скрыт». ⚠ Возможно владелец захочет
  пересечение прав (и то, и другое), а не главенство предка — но для «рука своего места» верно. Обратимо.
- **Дефолт (нет атома в цепочке) = поднимает любой** (открытый стол), в отличие от Private, где
  голый узел виден всем тоже — обе проекции «без атома = разрешено всем». Симметрично. Обратимо.

## Move (ход как один план) + admitsOccupied

- **Ход — чистый ПЛАН, не мутация.** `planMove` читает grab·grip·keeps·accept·occupied в порядке
  реального дропа и возвращает что БЫЛО БЫ; дерево применяет рантайм. Консистентно с «модель истина,
  вид локален» — план это данные, как всякий ответ кита. Обратимо.
- **Порядок гейтов фикс: grab→grip→keeps→accept→occupied.** Каждый умеет только ЗАПРЕТИТЬ, первый
  отказ побеждает, остальные моот. ⚠ Порядок — выбор (grip до keeps): «нельзя поднять» логически
  раньше «нельзя вынести». Обратимо (переставить).
- **Цель — «слот» ровно когда несёт `Displacer`; пайл без него не конфликтует, просто растёт.**
  У Container нет поля capacity — присутствие Displacer И заполненность = слот занят. Альтернатива —
  завести Container.capacity. Обратимо.
- **keeps проверяется по cap `"Draggable"`** (унос = перетаскивание). Имена способностей = имена
  АТОМОВ (как в accept/actions), не строчные ярлыки из иллюстрации в keeps.ts. Обратимо.
- **`admitsOccupied` вместо чтения `outcome.kind`** — гвард `guard.no-kind` (канон: поведение не
  читает сорт значения) краснел на `occupied.kind === "reject"` в move. Фикс канон-верный: ЗАПИСЬ
  Displacer’а сама объявляет `admits:boolean` рядом с `resolve()`, вызывающий спрашивает да/нет и
  не диспатчит по тегу. `resolveOccupied` остаётся непрозрачными данными плана для рантайма. Только
  `reject.admits=false`. Обратимо. Здесь всплыло: тег-юнион OccupiedOutcome кто-то в src обязан
  когда-то развернуть — но это работа рантайм-применителя на границе render, не чистых планировщиков.

## Deck (набор → карты)

- **`deck(specs)` — ПРЕСЕТ, строит узлы (как `arrow`/`line`), не данные-позы.** Готовое, где
  встречаются атомы карты: Bounded + Surfaced + (Flippable если back) + (Valued если values).
- **Flippable/Valued добавляются УСЛОВНО:** нет рубашки → карта односторонняя, нет атома переворота;
  нет данных → нет Valued. Личность карты — лицо и данные, не поведение. Обратимо.
- **НЕ интерактив:** deck не вешает Draggable/Grabber/Grippable — это вкус потребителя, не личность
  карты. Канон «не добавляй незапрошенного». Обратимо (сделать опцией).
- **Id = `${face}#${n}`**, уникально в пределах count. ⚠ Два спека с одним face столкнутся id —
  пока не защищено (спека набора обычно уникальны по лицу). Обратимо (префикс/счётчик глобальный).
- **Дефолт размер 1×1.4** — обычная карточная пропорция. Обратимо.

## Effects seam (`render/effects.ts`) — общий шов для Coated и Flippable

- **Один общий `EffectOut { node, pre, coats? }`** объединяет флиповский `{node, pre}` и
  surface-плановский `coats`. Альтернатива — два разных типа эффектов/два списка. Отвергнута:
  ядро складывает ОДИН список вслепую, поле `coats` опционально (флип его не ставит, coated —
  ставит). Обратимо (расширить/сузить структуру).
- **`coats` домешиваются в `scenePlan` (краска); `pre` будет домешиваться в `transformsOf`
  (геометрия, чтобы дошло до ДЕТЕЙ).** Оба места зовут одну чистую `applyEffects` (флип-хендофф
  §4 именно так). В этом коммите `transformsOf` НЕ тронут — для coated `pre=IDENTITY`, `node=n`,
  так что достаточно paint-стороны; геометрию подключит флип-эпик. Обратимо.
- **Coat-строка и coat-фильтр — last-wins override.** `Quad.stroke` один; ring-рецепт кладёт
  штрих → он ЗАМЕНЯЕТ штрих surface (кольцо выбора = граница, пока держится). Фильтр — тоже
  последний побеждает. ⚠ Замена (а не «поверх») теряет авторскую границу под кольцом; выбрано
  ради «один штрих на квад, не раздуваем ядро». Обратимо (можно сделать список штрихов).
- **`filter?: FilterRef` на `Quad` (не на слое)** — фильтр накрывает весь бокс квада в pixi
  (`box`-контейнер), а не отдельный слой. `FilterRef {name, params:Record<string,number>}` —
  сериализуемо, числа только. Обратимо.

## Coated (рантайм-слой поверх surface)

- **Тип `Paint` переехал в `core/paint.ts` (был `render/paint.ts` по плану).** Причина —
  `guard.layering`: `Coated.tint` (атом, core) не может импортить из render. Цвет-как-ДАННЫЕ —
  низ лестницы; резолв в hex (`theme.paint`) — верх. Отклонение от плана (там `render/paint.ts`),
  но иначе краснеет слоёвый гвард. Обратимо (это внутренний путь).
- **Параметрический цвет `spin` = `hsl(param*360, 70%, 55%)`, НЕ oklch/color-mix.** Причина: Pixi
  `fill({color})` не парсит oklch/color-mix надёжно, а hsl — да. Тема-независим осознанно (цвет
  команды/таймера — своя палитра игры, не стола), но остаётся ИМЕНЕМ (клиент может ремапнуть).
  Dangling-рецепт цвета → accent (мягко, не падение). Обратимо (сменить синтез в theme.ts).
- **Рецепты различаются ФОРМОЙ метки, а не значением/цветом.** `darken`/`charge`/`dim`/`fill` из
  плана СВЁРНУТЫ в один `wash` (заливка tint@opacity=level) — разница только в tint/level, а это
  ПАРАМЕТРЫ (урок Axis76), не отдельные записи. Отдельный рецепт заслуживает иная метка: штрих
  (`ring`), маска (`censor`), очистка (`clear`). Итог: wash/ring/censor/clear — 4 рецепта. ⚠
  Отклонение от списка плана (darken/charge/ring/dim/fill/censor); более канон-верно (нет
  записи-на-значение). Обратимо (добавить рецепты — это данные).
- **Охват `cast` (fromOwner): пустой дефолт NO_COAT ПРОЗРАЧЕН для наследования, явный `clear`
  ГЛУШИТ.** Проблема: атом всегда имеет дефолт, и generic `nearestAlongChain` вернул бы NO_COAT
  ребёнка, ломая каскад, как только ребёнок несёт Coated ради своего `self`-кольца. Решение —
  свой обход `nearestCast`, пропускающий `recipe===""`; рецепт `clear` (непустой) возвращает
  пустой RuntimeCoat и ОСТАНАВЛИВАЕТ обход → инверсия-прожектор («всё, кроме»). Отклонение от
  плана (там прямой `nearestAlongChain`); необходимо, иначе каскад ломается. Обратимо.
- **`installStockCoats()` регистрирует И рецепты, И эффект (idempotent-флаг), НЕ self-register на
  импорте.** Флип-хендофф предлагал self-register эффекта на импорте; отклонено ради без-side-effect
  импорта (норма кита: `installStockX`) и тест-изоляции (`resetCoats` сбрасывает флаг, тесты чисто
  переустанавливают после `resetEffects`). Обратимо.
- **`guard.coat-tint-is-token` СВЁРНУТ в существующий `guard.no-raw-colour`.** Отдельный гвард
  избыточен: hex в tint в исходнике уже забанен no-raw-colour. Рантайм-tint (игра передала hex) —
  забота игры, не кита. Добавлен только `guard.coat-not-viewer` (реально новый). ⚠ Обратимо
  (можно вернуть отдельный runtime-assert).

## Flippable (переворот как данные) — эпик flip

- **Flippable = `{ flip, turns, axis, back }` — поле `back` СОХРАНЕНО.** ⚠ Хендофф §1 удалял `back`,
  но не называл, где живёт изнанка карты для `turnOver`. Владелец (в §Context хендоффа) требовал
  «хранить в атоме ссылки / конфиг, чем узел СТАНЕТ». `back` как target-reference это и есть;
  рецепт `turnOver` его читает, `mirror` игнорит. Плюс: deck.ts `Flippable({back})` продолжает
  работать (fix-don't-delete), а не переписывается. Отклонение от §1 помечено. Обратимо.
- **`shownSurface(node, faceUp)` УДАЛЁН.** Заменён эффектом: он подменяет узел на изнаночный при
  нечётной СУММАРНОЙ чётности. `faceUp`-аргумент снаружи не нужен — сторона это паритет `turns`.
  Согласно хендоффу. Обратимо (git revert).
- **`reflect(deg)` — прямая матрица `[cos2θ, sin2θ; sin2θ, −cos2θ]`, НЕ `chain([rotate,scale,rotate])`.**
  Формула из хендоффа давала зеркало не по той оси (reflect(90) флипал y вместо x). Прямая матрица
  корректна: axis=90 = Y-зеркало (флип x), точка на оси неподвижна, det=−1, самоинверсна. Обратимо.
- **Эффект: отражение по СВОЕЙ чётности turns, подмена контента по СУММАРНОЙ.** Из этого кейс A
  выходит сам (два отражения по цепи гасятся). Проверено через реальный `transformsOf`. Хендофф §4.
- **`transformsOf` домешивает `pre` эффекта в трансформ узла** (геометрия-сторона шва, парная
  paint-стороне в scenePlan). Так отражение доходит до ДЕТЕЙ через цепь compose. scenePlan `pre` НЕ
  применяет повторно (только читает node+coats) — двойного отражения нет. Обратимо.
- **Рецепты: только `mirror` + `turnOver` (per-node).** `deckReorder`/`deckChildren`/`contentSwap`/
  `directionFlip` из хендоффа ОТЛОЖЕНЫ — они требуют swap на уровне ПОДДЕРЕВА в обходе walk (сложнее),
  а mirror/turnOver закрывают карту/контейнер/стопку (кейс A). ⚠ Отложено, не отменено. Обратимо.
- **`installStockFlips()` регистрирует рецепты + эффект (idempotent-флаг), как coats.** Не self-register.
- **Действие flip (turns+1) НЕ добавлено в actions.ts.** actions.ts — реестр меню `{label, requires}`,
  без исполнения; инкремент `turns` — работа оркестратора/потребителя, не кита. Хендофф §5 (compose-
  обработчик) отложен как вне личности атома. Обратимо.
