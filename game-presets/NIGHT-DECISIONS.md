## Установочные решения

- **Ветка от текущей ночной, не от `main`.** Пресеты потребляют `Flippable`/`deck`/`Surfaced`, которые
  живут на `night/2026-08-11-client2-mechanics` (36 неотправленных коммитов), а не на `main`. Альт:
  ветка от main + чекать, что движок доехал. Обратимо: rebase/merge позже.
- **Журнал эпика здесь (`game-presets/NIGHT-DECISIONS.md`), не в `game-kit/docs/design/`.** Движок не
  пачкаем решениями аддонов. Альт: дописывать в журнал fable. Обратимо: перенос файла.
- **Генератор — свой Node-скрипт `scripts/new-preset.mjs`, не plop.** Дом-стиль — кастомные `.mjs`
  (`game-kit/scripts/dev.mjs`), канон ценит минимализм и «ноль лишних зависимостей». Скрипт полностью
  наш, без handlebars. Альт: plop (стандартнее, но +dep). Обратимо: заменить генератор, шаблоны те же.
- **Порядок по слову владельца: генераторы → аддон → дальше.** Генератор штампует только ДОКАЗАННЫЙ
  скелет (мануфактура game-kit), контент игр — руками. Первый выхлоп генератора = скелет `cards`, он же
  его приёмка. «Правило трёх» соблюдено: генератор воспроизводит то, что game-kit уже доказал рабочим.
- **Дверь движка — `development` условие exports.** tsc резолвит через `customConditions:["development"]`
  (берёт `./src/index.ts` game-kit), vitest — через `resolve.conditions`. Обе стороны бьют в src,
  сборки game-kit не требуется. Это первый реальный потребитель условия — заодно живая проверка двери.
- **Скоуп генератора — только пакет-скелет**, без обвязки каталога Storybook. Каталог подключается
  руками на этапе демо. Альт: генератор правит и реестры каталога. Обратимо: добавить действия позже.
- **`workspaces += "game-presets/*"`** в корне (npm-воркспейсы, dep `game-kit: "*"`, не `workspace:*`).

## Дизайнерские решения по контенту (этапы 2–5)

- **Масти — один закрытый контур каждая (`fromSvgPath`), `d`-строки в `SUIT_PATHS` как единый
  источник.** И `Shape` (движок штрихует), и текстуры скина (SVG стампует) читают один и тот же путь.
  Бубна унифицирована как путь (была polyline). Геометрия клуба/пики авторская, приближённая —
  узнаваемая, не претендует на идеал; уточнить при желании. Обратимо: правка строки.
- **Цвет: красный = `spin@0` (одна краснота на обе масти, как «одно золото»), чёрный = токен `text`.**
  В текстурах — CSS-имена (`black`/`crimson`), т.к. картинка — контент, не следует теме (красное
  остаётся красным на тёмном столе). Изъятие сторожа `no-raw-colour` — только папка `textures/`.
- **Набор моделирует свою лёгкую схему типов** (`CROSSADE_FIELDS`: suit/rank/colour как `ordered`,
  `values` = порядок сортировки), т.к. `ElementSet` движка ещё не построен (sets.md — «спроектировано»).
  Цвет пипса выводится из масти (один источник). Альт: ждать ElementSet. Обратимо: заменить на него.
- **Лицо карты = самодостаточная SVG-текстура (белый фон+индексы+пипсы), поверхность — просто image
  cover + радиус.** Причина: пейнтер не ставит N пипсов в одном узле без детей, а `deck()` строит
  плоские карты (без детей). Текстура переиспользует вектор-пути мастей (та же геометрия). Раскладка
  пипсов 2–10 — классическая (`LAYOUTS`), нижняя половина повёрнута на 180°. Альт: пипсы как узлы-дети
  (нужен контейнер вместо `deck()`) — отложено. Обратимо: скин перерегистрируется.
- **`cards()` по умолчанию ставит classic-скин** (батарейки в комплекте: один вызов — карты видны),
  `install:false` отдаёт скин потребителю. Побочный эффект регистрации осознан. Обратимо: флаг.
- **id узлов — `deck()`-дефолт `${face}#${n}`** (`cards/face/spade-A#0`): опаковые, уникальные.

## Демо в каталоге (этап 6)

- **Демо — отдельная группа верхнего уровня `Add-ons/Cards`, не под `Presets`.** Провенанс структурой:
  аддон стоит ВНЕ ядра. Альт: `Presets/Cards` (смешивает с ядром). Обратимо: строка `storySort.order`.
- **game-kit получает `customConditions:["development"]` + devDep `@game-presets/cards`.** Иначе tsc
  каталога резолвит аддон в несуществующий `dist`. Каталог импортирует аддон ПО ИМЕНИ (через дверь),
  а не путём в src — поэтому `guard.catalog-through-the-door` не срабатывает. Обратимо: убрать dep.
- **Провенанс — в прозе локалей** (`docs.cards.component`): явно «всё это аддон, движок не несёт
  ни картинки, ни набора». Абстрактный reference-ярус `Atoms/*` не тронут.
- **Каталог собирается только `npm run dev` (Vite dev → условие development → src).** Прод-сборка
  (`storybook build`) ушла бы в `dist` аддона/движка, которых нет. Для статической сборки каталога
  оба пакета надо сперва собрать в `dist`. Записано как известное ограничение, не блокер dev.
